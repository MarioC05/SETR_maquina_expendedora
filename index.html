Práctica: Máquina expendedora de café

1. INTRODUCCIÓN

El objetivo de esta práctica es la creación de una máquina de café usando un "Super Starter Kit UNO R3 Project" de Arduino. hemos usado estos componentes:

  • Arduino UNO
  • Pantalla LCD
  • Módulo Joystick
  • Sensor de Temperatura y Humedad DHT11.
  • Sensor de Distancia por Ultrasonidos
  • Pulsador / Botón externo.
  • 2 LEDs estándar

Gracias a ellos, hemos implementado las siguientes funcionalidades:

  • Modo arranque con un led que nos indique cuánto falta por medio de parpadeos.
  • Detector de presencia que inicie la máquina cuando alguien se acerque.
  • Display de productos y precios por el que se pueda navegar.
  • Indicador de cuánto falta para terminar el café por medio de un led que cambia su intensidad.
  • Modo admin que permite visualizar los sensores libremente además de modificar los precios.

Ahora explicaremos como hemos afrontado los retos y explicaremos las partes del código más importantes.

2. SOLUCIÓN PROPUESTA

2.1 ESTRUCTURA DEL CÓDIGO

Al tener la máquina de café varios modos de funcionamiento, de los cuales se pueden pasar de uno a otro dependiendo de ciertos eventos, he optado por realizar una máquina de estados. Para mantener la reactividad del sistema, hemos realizado la mayor parte del código dentro del loop principal, donde en cada ciclo comprobaremos en que estado estamos, y ejecutaremos el código acorde. Para complementar la reactividad del sistema, hemos hecho uso de ArduinoThreads y un controlador para manejarlos, para así poder evitar el uso de delays sin tener necesariamente que ejecutar el código de cada modo en todos y cada uno de los bucles. Las únicas acciones que no se realizan en bucle son las del setup, que incluyen inicialización de pines, asignación de callbacks y periodos a los threads y creación de interrupciones hardware. Normalmente, cada estado tiene un solo thread asociado, y este a su vez se fija en un solo sensor. Las únicas excepciones son el thread que se encarga de mirar el botón externo (pues sirve para cambiar de modo independientemente del estado actual), y el estado ADMIN_ACTION, que se le pueden asociar hasta 4 threads diferentes (ya lo veremos en profundidad más adelante). La función de la máquina de estados casi siempre se limita a activar y desactivar threads en el controlador, y luego son estos threads los que se encargan de gestionar cuando se pasa al siguiente estado. A veces, sin embargo, la máquina de estados se puede encargar de comprobaciones más simples que no requieran lectura constante de sensores, como comprobar si ha pasado cierto tiempo desde que entro a ese estado. La única interrupción hardware es la del botón incluido en el joystick. Para evitar romper la reactividad, en ella simplemente cambiamos un booleano que nos indica que el joystick se ha pulsado. Esta variable se comprobará luego en los threads pertinentes. Para evitar que una pulsación erronea del joystick cuando no tocaba modifique comportamientos futuros, se restablece el valor de esta variable automáticamente cada 2 segundos, junto con otras variables que tienen el mismo problema.

void joyClick() {
joystickClicked = true;
}

Ahora explicaremos cada estado en mayor profundidad.

2.2 ESTADOS

ARRANQUE:

Es el estado que se ejecuta nada más encender la placa. En este estado habilitamos el siguiente thread con periodo de 1 segundo:

void ledBlink() {

if(n_blink < 3){

led1state = !led1state;

digitalWrite(LED1, led1state);

if (!led1state) {
n_blink++;
}

} else {

state = SERVICIO;

}

}

Este código se encarga de ir alternando un led de encendido y apagado cada vez que se ejecuta (1 segundo). Cuando se repita el parpadeo 3 veces, se pasa al siguiente estado.

SERVICIO:

Este estado ocurre tras el arranque y siempre que se resetea por medio del botón externo. Aquí está el código asociado:

void detectPeople() {

digitalWrite(TRIG, LOW);
delayMicroseconds(2);

digitalWrite(TRIG, HIGH);
delayMicroseconds(10);
digitalWrite(TRIG, LOW);

unsigned long echo = pulseIn(ECHO, HIGH, 30000);

//vel sonido = 343m/s
float dist = echo / 58.0;

if (dist > 0 && dist < 100) {

state = SERVICIO_TEMP;

}

}

Con el detector de ultrasonidos, esperamos 2 ms con el emisor apagado para estabilizar la señal, luego mandamos una onda por 10 ms. Tras ello, recibimos por el receptor durante 30 ms por si rebota la señal. Si conseguimos detectar
algo, usamos la fórmula para convertir el tiempo transcurrido en distancia, y comprobamos si está a menos de 1 metro. Si la respuesta es afirmativa, pasamos al siguiente estado. Este es el único estado que rompe ligeramente la
reactividad del programa usando delayMicroseconds, pero solo durante 42 ms.

SERVICIO_TEMP:

Este estado dura 4 segundos, los cuales comprobaremos dentro del propio loop usando la función millis(), y comparándola con el tiempo que obtuvimos al entrar en el estado. mientras tanto, mostraremos la temperatura y la humedad con este código que se ejecutará cada 1 segundo, pues el DHT no cambia su detección con mucha frecuencia:

void checkTemp() {

if ((millis() - last_time) <= 5000) {

float t = dht.readTemperature();
float h = dht.readHumidity();

lcd.setCursor(0, 0);
lcd.print("Temp: ");
lcd.print(t);
lcd.print(" C   ");
Serial.print("Temp: ");
Serial.print(t);
Serial.println("C");

lcd.setCursor(0, 1);
lcd.print("Humedad: ");
lcd.print(h);
lcd.print(" %   ");
Serial.print("Humedad: ");
Serial.print(h);
Serial.println("%");

} else {

state = SERVICIO_SELECT;

}

}

SERVICIO_SELECT:

Una vez pasados los 4 segundos, entraremos en este estado en el que mostraremos por pantalla los productos y sus precios. Para moverse por ella, veremos si el valor del eje y del joystick se aleja mucho del centro por arriba y por abajo. El periodo de este checkeo es de 500 ms, ni mucho, para que no tarde en cambiar de producto, ni muy poco, para que no cambie demasiado deprisa y no podamos controlarlo.

void selectDrink() {

Solo actualizaremos la placa cuando se cambie de bebida para evitar parpadeos innecesarios. Para seleccionar una bebida, comprobaremos la interrupción hardware del botón en el joystick que mencionamos antes. Esto lo haremos fuera del
thread, en la máquina de estados, para no tener que esperar a que se ejecute.

if (joystickClicked) {

joystickClicked = false;

state = SERVICIO_PREP;

}

SERVICIO_PREP:

Una vez se seleccione la bebida, la prepararemos durante un intervalo de tiempo aleatorio entre 4 y 8 segundos. Para mostrar el progreso, cambiaremos la intensidad de un led según el porcentaje de completitud:

void increaseBright() {

if ((millis() - last_time) <= prep_time){

int bright = map((millis()-last_time), 0, prep_time, 0, 255);

bright = constrain(bright, 0, 255);

analogWrite(LED2, bright);

} else {

state = SERVICIO_WAIT;
last_time = 0;

}

}

SERVICIO_WAIT:

Cuando termine de hacerse el café, simplemente esperaremos 3 segundos a que se retire la bebida, y luego volveremos a pasar a SERVICIO. No hay ningún thread asociado a este estado.

ADMIN:

A este estado se accede gracias al botón externo, y se puede volver de él al estado servicios de la misma manera. En el, tenemos un selector de opciones que funciona similar el selector de bebidas, comprobando el joystick para poder pasar por todas las acciones disponibles:

void adminMenu() {

int joy_y = analogRead(JOY_Y);

if (joy_y < 312) {
if (n_action > 0){
n_action--;
}
}

if (joy_y > 712) {
if (n_action < 3){
n_action++;
}
}

if (n_action != last_n_action){

lcd.clear();

lcd.setCursor(0, 0);
lcd.print(actions[n_action]);
Serial.println(actions[n_action]);

last_n_action = n_action;
}

}

Sin embargo, a diferencia del selector de bebidas, que no cambia su funcionamiento según la bebida que elijas, aquí si que importará el modo seleccionado. Una vez presiones el joystick (comprobado del mismo modo que antes) entraremos al
estado ADMIN_ACTION, pero habilitaremos un thread diferente dependiendo de la acción elegida.

ADMIN_ACTION:

Como hemos mencionado antes, este estado puede tener 4 threads diferente asociados. La cosa en común que todos tienen es que si giras el joystick a la izquierda, volverá al estado anterior. Los estados son los siguientes:

4) Permite cambiar los precios. Es el más complejo de los 4 así que lo explicaremos más a fondo:

void adminPrices(){

int joy_x = analogRead(JOY_X);
int joy_y = analogRead(JOY_Y);

if (joy_x > 712) {
if (n_drink < 4){
n_drink++;
} else {
n_drink = 0;
}
}

if (joy_y < 312) {
if (new_price[n_drink] > 0){
new_price[n_drink] = new_price[n_drink] - 0.05;
}
}

if (joy_y > 712) {
new_price[n_drink] = new_price[n_drink] + 0.05;
}

if (n_drink != last_n_drink || new_price[n_drink] != last_new_price){

lcd.clear();

lcd.setCursor(0, 0);
lcd.print(drinks[n_drink]);
Serial.print(drinks[n_drink]);

lcd.setCursor(0, 1);
lcd.print(new_price[n_drink], 2);
lcd.print(" EUR");
Serial.print(new_price[n_drink]);
Serial.println("EUR");

last_n_drink = n_drink;
last_new_price = new_price[n_drink];
}

if (joystickClicked){
joystickClicked = false;

price[0] = new_price[0];
price[1] = new_price[1];
price[2] = new_price[2];
price[3] = new_price[3];
}

}

Cuando entremos en esta acción, nos crearemos una copia del listado de precios actuales. El display es parecido al selector de bebidas, pero el eje y del joystick servirá para bajar o subir los precios de 0.05 en 0.05. Para movernos
entre las bebidas, en cambio, moveremos el joystick a la derecha como el joystick hacia la izquierda está reservado para cancelar la acción, simplemente hemos cerrado el lazo de las bebidas para que puedas volver atrás). Cuando
pulsemos el joystick, todos los cambios en los quedarán guardados y se verán cuando volvamos a iniciar el modo de servicios.

Botón Externo:

Pese a no ser un estado como tal, merece la pena explicarlo. Este es el único thread que está activo siempre:

void checkButton() {

bool buttonState = digitalRead(BUTTON);

if (buttonState == LOW && !buttonPressed) {

buttonPressed = true;
start_press = millis();

}

if (buttonState == HIGH && buttonPressed) {

buttonPressed = false;
total_press = millis() - start_press;

}

}

Se ejecuta con un periodo de solo 100 ms y comprueba si el botón está pulsado. La próxima vez que se ejecute y el botón ya no esté pulsado, calculará el intervalo de tiempo que ha estado pulsado, y usará el valor obtenido para cambiar
de estados según las especificaciones de la práctica:

if(total_press > 2000 && total_press < 3000) {
state = SERVICIO;
total_press = 0;

led2Thread.enabled = false;
analogWrite(LED2, 0);
}

if(total_press >= 5000) {

if (state != ADMIN && state != ADMIN_ACTION){

state = ADMIN;

digitalWrite(LED1, HIGH);
digitalWrite(LED2, HIGH);

total_press = 0;

led1Thread.enabled = false;
ultrasonicThread.enabled = false;
dhtThread.enabled = false;
joyThread.enabled = false;
led2Thread.enabled = false;

} else {

state = SERVICIO;

digitalWrite(LED1, LOW);
digitalWrite(LED2, LOW);

total_press = 0;

joyAdminThread.enabled = false;
dhtAdminThread.enabled = false;
ultrasonicAdminThread.enabled = false;
timeAdminThread.enabled = false;
priceAdminThread.enabled = false;
}

}

Watchdog:

Además del funcionamiento base, hemos implementado un watchdog al programa, que comprueba si este se ha bloqueado. Para ello, ejecutamos este comando en cada bucle:

wdt_reset();

Si este comando no se ejecuta como mínimo cada 2 segundos valor que hemos asignado nosotros), entenderemos que el programa se ha bloqueado y se reiniciará la placa
